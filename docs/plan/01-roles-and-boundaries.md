# 角色与边界

## 1. 总原则

- **单目录单一所有者**：任何目录一次只允许一个 Agent 直接修改，例外是共享契约与 CI/文档。
- **契约先行**：字段变更先改 `openapi.yaml`，再实现代码。
- **互相不越界**：后端不写页面样式，前端不直接改数据库或业务逻辑。
- **争议由契约仲裁**：联调问题优先回到契约，而不是互相口头妥协。

## 2. Agent A：后端（Deepseek-V4-Pro）

### 职责

- 设计并实现 `apps/api`。
- 维护 `openapi.yaml`（作为契约的**起草方**）。
- 维护 `packages/contract` 中的共享 schema 与类型生成脚本。
- 数据库建模、迁移、种子数据。
- 认证、授权、限流、审核、搜索、上传、日志与监控。
- 后端单元 / 集成 / 契约测试。

### 所有权

| 目录 / 文件 | 权限 |
| --- | --- |
| `apps/api/**` | 独占修改 |
| `openapi.yaml` | 可提议修改，须双审后合并 |
| `packages/contract/**` | 可提议修改，须双审后合并 |
| `docs/plan/02-backend-task-plan.md` | 独占维护 |
| 其他目录 | 只读 |

### 禁止

- 修改 `apps/web/**`、`public/**`、前端设计 token 与美术资产。
- 在未更新契约的情况下修改接口字段。
- 直接向 `main` / `develop` 推送。

## 3. Agent B：前端（Kimi k3）

### 职责

- 设计并实现 `apps/web`。
- **整体美术导向**：视觉风格、配色、字体、组件库、动效、响应式与无障碍。
- 页面、路由、SSR/ISR、SEO、客户端交互。
- 维护设计 token、Storybook 或组件文档。
- 消费契约生成的类型与 mock 数据。
- 前端测试与视觉回归。

### 所有权

| 目录 / 文件 | 权限 |
| --- | --- |
| `apps/web/**` | 独占修改 |
| `public/**` | 独占修改 |
| 设计系统文档（如 `docs/design/**`） | 独占维护 |
| `docs/plan/03-frontend-task-plan.md` | 可审查并修改 |
| 其他目录 | 只读 |

### 禁止

- 修改 `apps/api/**`、数据库 schema 或业务逻辑。
- 绕过契约硬编码字段。
- 直接向 `main` / `develop` 推送。

## 4. 共享所有权

| 目录 / 文件 | 规则 |
| --- | --- |
| `openapi.yaml` | 后端起草，前端必须 review；双审通过才可合并 |
| `packages/contract/**` | 后端生成，前端消费；双审 |
| `.github/**`、根配置 | 仓库所有者统筹，两个 Agent 可提 PR |
| `docs/**` | 各自维护对应计划文档；交叉审查 |

## 5. 决策与评审流程

1. **Deepseek 起草**完整计划（本仓库 `docs/plan/*` 初稿）。
2. **Kimi 审查**，重点审阅 `docs/plan/03-frontend-task-plan.md` 与契约中影响前端体验的字段。
3. Kimi 可提出修改，修改需落在对应文档并以 PR 说明理由；后端据此更新契约草案。
4. 双方在 `contract/*` 分支就 `openapi.yaml` v1 达成一致，标记冻结。
5. 冻结后进入并行开发；如需变更，走契约变更流程（见 06）。

## 6. RACI 速览

| 事项 | 后端 | 前端 | 仓库所有者 |
| --- | --- | --- | --- |
| 后端实现 | R / A | I | C |
| 前端实现 | I | R / A | C |
| 契约起草 | R / A | C | I |
| 契约批准 | R | R | A（冲突仲裁） |
| 美术导向 | I | R / A | C |
| 分支权限 | C | C | R / A |
| 发布 | C | C | R / A |

（R=执行，A=负责，C=咨询，I=知会）
