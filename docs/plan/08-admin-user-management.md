## 1. 权限模型（四层，参考 Discuz / Discourse / 贴吧通行做法）

### 1.1 用户组 UserGroup（决定内容能力）

| 组 | 获得方式 | 能力 |
| --- | --- | --- |
| normal 普通 | 注册即得 | 仅阅览（浏览 Wiki/攻略/论坛） |
| verified 认证 | 手机号验证通过 | normal + 评论、论坛发帖/回复、点赞收藏 |
| premium 付费 | 未来付费（本期预留） | verified + 高级内容访问位（预留字段） |

> 影响说明：按你的规则，**新注册用户默认只有阅览权**，评论/发帖需认证。
> 现有站长账号为最高管理员，不受影响。

### 1.2 通用等级 Level（1–10）

- 站内通用等级，展示于用户中心与作者位；站长可在用户管理中手动调整。
- 本期仅做展示与手动设置；未来可扩展自动升级或访问门槛（如等级≥3 发图）。

### 1.3 管理身份 Role（决定管理权限）

| 角色 | 说明 |
| --- | --- |
| owner 站长 | **最高权限管理员**（chiyuan222）；拥有全部权限；唯一可授予/回收管理员身份与权限开关 |
| admin 一级管理员 | 由站长授予；权限按开关控制，默认无任何管理权限 |
| moderator 版主 | 可选；并入开关体系（同 admin 机制，可后续启用） |
| member / editor / guest | 普通身份（editor 保留给内容贡献者） |

### 1.4 权限开关 Permissions（管理员能力位，由站长单独勾选）

每个 admin/moderator 用户维护一组开关（默认全关，站长逐个开启）：

- `manage_users`：查看用户列表/详情、封禁/解封、改用户组/等级
- `manage_content`：管理词条/帖子（改状态、删除、精华/置顶）
- `manage_forum`：论坛板块与分类管理
- `manage_cms`：首页/总览页 CMS 编辑
- `grant_wiki_create`：授予普通用户「创建 Wiki 词条」资格

**Wiki 词条创建资格**：与管理员开关分开，作为用户身上的独立能力位
（`wikiCreateGranted`），只能由站长授予——普通用户即使有该能力位也只能创建词条，不能管理。

## 2. 封禁体系（三种状态，分级处理）

| 状态 | 行为 |
| --- | --- |
| active 正常 | 全功能 |
| muted 禁言 | 保留登录与浏览，禁止评论/发帖/回复/点赞（可选截止时间） |
| banned 黑名单 | 禁止登录与访问站点（会话全部失效，可选截止时间 + 原因） |
| deleted 注销 | 现有软注销，保持 |

封禁/解禁操作记入后台日志（操作人、时间、原因），供站长审计。

## 3. 站内统计（站长总览）

### 3.1 指标

| 指标 | 口径 |
| --- | --- |
| 总用户数 / 今日新增 | 注册计数 |
| 站内浏览量 PV | 全部请求计数（按天） |
| 独立访客 UV | 按 IP 去重（按天） |
| 日活跃 DAU / 月活跃 MAU | 登录用户按天/按月去重 |
| 当前在线人数 | 最近 15 分钟内有活动的登录会话数 |
| 内容热度 Top N | 详情页浏览量排行（Wiki/攻略/论坛） |

### 3.2 数据模型

- `DailyStat`（date 唯一）：pv、uv、dau
- `DailyActiveUser`（userId + date 唯一）：日活明细（用于月活去重）
- `Session.lastActiveAt`：在线判定
- `ContentView`（kind + slug 聚合计数）：内容热度（详情页浏览时 +1）

## 4. 管理端点（contract 新增）

1. `GET /admin/stats/overview` —— 站长总览：用户数/今日新增/PV/UV/DAU/MAU/在线人数/Top 内容
2. `GET /admin/users` —— 用户列表（搜索用户名/邮箱/手机号，筛 group/role/status/level，分页）
3. `GET /admin/users/{userId}` —— 用户详情（含权限开关、封禁信息）
4. `PATCH /admin/users/{userId}` —— 改 group/level/status（封禁/解禁/禁言）、
   `wikiCreateGranted`、`permissions`；其中 role 变更与权限开关**仅 owner 可操作**

权限：以上端点仅 owner 与「已开启对应权限开关」的 admin 可访问，否则 403；
敏感操作（封禁/解禁/改 role）要求操作人具备 `manage_users` 开关。

## 5. 内容写权限调整（联动 PR #50）

PR #50 合并后，写操作按新权限模型执行：

- 评论/论坛发帖：`verified` 及以上组；`muted`/`banned` 拒绝（403/401）
- 创建 Wiki 词条：`wikiCreateGranted` 或拥有 `manage_content` 开关的管理员
- 编辑/删除他人内容：仅作者或具备 `manage_content` 开关的管理员
