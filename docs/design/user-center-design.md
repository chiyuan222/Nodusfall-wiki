# 用户中心与真实账号体系 — 前端设计方案

> 版本：v0.1（待评审）　范围：注册 / 登录 / 用户中心 / 账号生命周期
> 承接需求：①外部注册（真实邮箱验证码 + 手机号格式校验）②登录后登录键替换为用户中心
> ③用户中心：我的主页、我的内容（帖子/收藏/评论）、浏览记录、账号设置（绑定状态/注销）、退出

---

## 1. 目标与原则

- 让「登录」成为站内身份的起点：注册即拥有真实联系方式，登录后全站 header 呈现用户身份。
- 延续现有「结绳源点（Nodus Origin）」设计语言，不引入新的视觉体系。
- 合规优先：注册需同意《用户协议》《隐私政策》；邮箱/手机号对外脱敏；注销权、浏览记录可清空、验证码防轰炸。

## 2. 页面与信息架构

### 2.1 新增页面

| 页面 | 路由 | 说明 |
| --- | --- | --- |
| 注册页 | `/register` | 邮箱注册 / 手机号注册双 Tab |
| 用户协议 | `/legal/terms` | 静态页，注册勾选时引用 |
| 隐私政策 | `/legal/privacy` | 静态页，说明收集项、用途、注销与删除权利 |

### 2.2 改造页面

| 页面 | 路由 | 改动 |
| --- | --- | --- |
| 登录页 | `/login` | 支持「邮箱 或 手机号 + 密码」；页脚加「没有账号？去注册」 |
| 用户中心 | `/me` | 由「资料卡 + 我的内容」升级为四区块 Tab 页 |
| 全站 header | 全局 | 「登录」按钮替换为「用户中心」入口（含下拉） |

### 2.3 用户中心 `/me` 结构（四 Tab）

```
用户中心
├─ 我的主页（默认 Tab）
│   头像 / 昵称 / @用户名 / 角色徽标 / 简介 / 注册时间
│   [编辑资料]（昵称、头像、简介）[退出登录]
│   绑定状态卡：邮箱 x****@xxx.com（已绑定）· 手机号 138****1234（未绑定/待接入）
├─ 我的内容
│   Tab：我发布的主题 / 我的收藏 / 我的评论
├─ 浏览记录
│   最近浏览（Wiki/攻略/论坛），按时间倒序，[清空记录]
└─ 账号设置
    注销账号（密码确认 + 二次确认 + 合规说明）
```

说明：

- 公开主页（他人视角 `/users/{id}`）本次不做，仅做「我的主页」；可后续迭代。
- 「换绑」按需求跳过，账号设置只展示绑定状态，不提供换绑入口。
- 移动端延续底部 TabBar 的「我的」入口，登录后显示头像缩略圆点。

## 3. 核心交互流程

### 3.1 注册（邮箱验证码）

1. 选择「邮箱注册」，输入邮箱 → 点击「获取验证码」。
2. 前端 60s 倒计时；后端限流（同一邮箱 60s 一次、每日上限，防止轰炸）。
3. 输入 6 位验证码 + 用户名 + 密码（≥8 位）+ 勾选《用户协议》《隐私政策》。
4. 注册成功 → 自动登录 → 跳转 `/me`。

### 3.2 注册（手机号，暂为格式校验）

1. 选择「手机号注册」，输入 11 位大陆手机号（前端 + 后端双重格式校验）。
2. 输入用户名 + 密码 + 协议勾选。
3. 页面提示「手机号暂未开通短信验证，绑定验证将在接入短信服务后开启」。
4. 注册成功 → 自动登录 → 跳转 `/me`。

> 说明：短信验证码按用户决策延后到腾讯云部署时接入；当前手机号仅做真实性格式校验，不做短信确认。

### 3.3 登录

- 输入框支持自动识别：含 `@` 视为邮箱，11 位数字视为手机号。
- 错误提示沿用现有风格（401 →「邮箱/手机号或密码不正确」；429 → 带秒数提示）。
- 登录成功 → 跳转 `/me`（用户立刻看到登录态，解决「登录后没有变化」的盲区）。

### 3.4 Header 登录态（核心改动）

新增客户端组件 `AuthMenu`（替代现有静态「登录」按钮）：

- 未登录：显示「登录」「注册」两个按钮。
- 已登录：显示头像圆点 + 昵称，hover/点击展开下拉：
  - 用户中心（/me）
  - 我的内容 / 浏览记录 / 账号设置（锚点或子路由）
  - 退出登录
- admin 额外显示「后台」入口。
- 实现要点：用 `getAccessToken()` 判断是否登录，首次进入调 `GET /users/me` 取昵称/头像/角色；401 时自动降级为未登录态。

### 3.5 浏览记录

- 登录用户访问 Wiki 详情 / 攻略详情 / 论坛主题页时，组件挂载时上报一次 `POST /users/me/history`。
- `/me` 浏览记录 Tab：分页倒序列表（封面 + 类型标签 + 标题 + 时间），提供「清空记录」按钮（二次确认）。
- 仅记录登录用户；不记录匿名浏览。

### 3.6 注销（软注销，合规流程）

1. 账号设置 →「注销账号」→ 红色警示文案：
   - 「注销后账号将无法登录；你发布的帖子、攻略与评论会保留，但作者显示为『已注销用户』。」
2. 输入当前密码确认 → 二次确认对话框（输入「注销」或勾选确认）→ 提交。
3. 成功后清除本地会话 → 跳转首页，header 恢复未登录态。

## 4. 视觉设计（贴合现有 token）

全部沿用 `tokens.css`「结绳源点」体系，不新增色板：

| 元素 | 规范 |
| --- | --- |
| 页面卡片 | `bg-surface` + `border-subtle` + `rounded-md`，列表项 hover `bg-raised` |
| 注册/登录表单 | 与现有登录表单一致：`bg-raised` 输入框、琥珀主按钮 |
| Tab | 沿用 `MyContent` 的 tablist 风格（`rounded-md px-4 py-1.5`，激活 `bg-raised text-amber`） |
| 头像占位 | 沿用现有：首字母 + 琥珀圆底；不引入图片裁切组件 |
| 危险操作（注销） | `semantic-danger` 红 + 描边按钮，禁用态 40% 透明 |
| 验证码按钮 | 琥珀文字按钮 + 60s 倒计时（`font-mono text-caption`） |
| 脱敏展示 | 邮箱 `x****@xx.com`、手机号 `138****1234`（`font-mono text-faint`） |
| 动效 | `dur-fast` 过渡 + `ease-out`；危险操作无弹跳动效 |

三套主题（默认 / starlight / oracle）由 token 自动适配，无需额外工作。

## 5. 合规设计（随本次一并落地）

- 注册必须勾选《用户协议》《隐私政策》；协议页说明收集字段（邮箱/手机号/用户名/浏览记录）与用途。
- 邮箱/手机号仅对本人可见（脱敏展示），`UserSummary` 不返回任何联系方式。
- 浏览记录仅本人可见，提供一键清空。
- 注销权：软注销后账号不可登录、会话全部失效；内容匿名化保留。
- 验证码防轰炸：发送间隔 60s、单日上限、验证码有效期与尝试次数限制（后端实现）。
- 密码存储保持 bcrypt；手机号待短信接入后加密/脱敏存储。

## 6. 后端契约对应（本轮新增端点概览）

| 端点 | 用途 |
| --- | --- |
| `POST /auth/email-codes` | 发送邮箱验证码（限流） |
| `POST /users`（改造） | 注册：邮箱+验证码 或 手机号（格式校验） |
| `POST /auth/sessions`（扩展） | 登录支持手机号 |
| `GET /users/me/comments` | 我的评论（分页） |
| `GET /users/me/history` | 我的浏览记录（分页） |
| `POST /users/me/history` | 上报一次浏览 |
| `DELETE /users/me/history` | 清空浏览记录 |
| `DELETE /users/me` | 软注销（密码确认） |

详细字段走 `contract/*` PR（openapi.yaml 冻结后 @Kimi 确认），本方案不展开。

## 7. 实施步骤

1. 方案评审（本文件）→ 用户确认。
2. 后端：`contract/*` PR 更新 openapi.yaml → @Kimi 确认 → 合并。
3. 后端：`backend/*` PR 实现验证码 / 注册登录扩展 / 用户中心端点 / 浏览记录 / 软注销。
4. 前端：本设计落地（含 `AuthMenu`、注册页、/me 四 Tab、注销流程）→ `frontend/*` PR。
5. 联调：注册→验证码→登录→header 变化→收藏/评论/浏览记录→注销，端到端回归。
